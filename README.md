## 📖 Plain-English Guide: What We Have Done in Sprint 1

In Sprint 1, we focused on two major goals: getting the image data ready and building the frontend authentication interface.

### Step 1: Image Dataset Collection (Task 1)
- We gathered a total of **132,000 images** to train and test our detector.
- The dataset combines two primary sources:
  1. **CIFAKE:** Real images from CIFAR-10 versus synthetic images generated by Stable Diffusion v1.4.
  2. **GenImage:** Real images and AI images created by multiple state-of-the-art generators (Stable Diffusion, Midjourney, BigGAN) used as our holdout benchmark.
- All paths, labels (`0` for real, `1` for AI-generated), and generator metadata are stored cleanly in [`datasets/splits/manifest.csv`](datasets/splits/manifest.csv).

### Step 2: Balanced Dataset Splits with Zero Leakage (Task 2)
- To ensure fair evaluation without bias, we divided the 132,000 images into four partitions:
  - **Train split:** 90,000 images (45,000 real, 45,000 AI) — exactly 50% / 50%
  - **Validation split:** 10,000 images (5,000 real, 5,000 AI) — exactly 50% / 50%
  - **In-domain Test split:** 20,000 images (10,000 real, 10,000 AI) — exactly 50% / 50%
  - **Out-of-domain Holdout split:** 12,000 images (6,000 real, 6,000 AI) — exactly 50% / 50%
- **Zero Data Leakage:** We strictly verified that no image appears in more than one partition. The split generation was done with a fixed random seed (`42`) so it can be repeated with 100% identical results.
- **Verification:** Run `python3 scripts/verify_sprint1_splits.py` or `pytest tests/test_dataset_splits.py`.

## 📖 Plain-English Guide: What We Have Done in Sprint 2

In Sprint 2, we built the actual image detection machine learning engine, wrapped it into an API, and added high-performance batch processing.

### Week 1: Core Image Detection Inference Engine (Task 1)
- **Model Choice:** We implemented a forensic classifier based on **ResNet-18** (`BaselineImageClassifier` in [`src/image_detector/model.py`](src/image_detector/model.py)).
- **Hardware Acceleration:** The code automatically detects your system's hardware. On an Apple Silicon Mac, it automatically runs on the Mac GPU using PyTorch `mps` (Metal Performance Shaders). On an NVIDIA machine, it runs on `cuda`. If no GPU is found, it safely falls back to CPU.
- **Image Preprocessing:** In [`src/image_detector/preprocessing.py`](src/image_detector/preprocessing.py), incoming images can be uploaded as raw file bytes, Base64 strings, or file paths. It converts images to standard 3-channel RGB, resizes them to 224x224 pixels, and normalizes them for the neural network.
- **Standardized Output Contract:** Every prediction returns a clean, typed response format:
  - `verdict`: `"REAL"` or `"AI_GENERATED"`
  - `confidence`: Confidence score from 0.0 to 1.0 (e.g., `0.9985`)
  - `probabilities`: Individual probabilities for `real` and `ai_generated`
  - `image_metadata`: Width, height, channels, and format
  - `latency_ms`: Processing time in milliseconds
  - `device`: Hardware device used (`mps`, `cuda`, or `cpu`)
- **Verification:** Run `python3 scripts/verify_sprint2_week1.py` or `pytest tests/test_image_inference_service.py`.

### Week 2: REST API & 6 Security Guardrails (Task 1)
- **FastAPI Endpoints:** Created in [`src/image_detector/api.py`](src/image_detector/api.py) and hosted as a standalone service in [`services/image-service/app/main.py`](services/image-service/app/main.py) on port `8004`:
  - `POST /api/detect/image`: Direct multipart file upload.
  - `POST /api/detect/image/base64`: Ingests Base64 image payloads.
  - `GET /internal/health`: Live health and hardware diagnosis endpoint.
  - `/docs`: Interactive Swagger UI in the browser.
- **6 Security Guardrails:** The API strictly validates every request and returns clear HTTP status codes:
  1. *Valid Upload:* Returns `200 OK` with the prediction.
  2. *Empty File:* Returns `400 Bad Request` if file has 0 bytes.
  3. *File Too Large:* Returns `413 Payload Too Large` if file exceeds 15 MB.
  4. *Unsupported Extension:* Returns `415 Unsupported Media Type` if not `.png`, `.jpg`, `.jpeg`, or `.webp`.
  5. *Spoofed Extension:* Returns `415 Unsupported Media Type` by checking actual magic byte file signatures (e.g., preventing an `.exe` file renamed to `.png`).
  6. *Corrupted File / Out-of-bounds Dimensions:* Returns `422 Unprocessable Entity` if the image cannot be decoded or is smaller than 16x16 or larger than 8192x8192.
- **Verification:** Run `python3 scripts/verify_sprint2_week2.py` or `pytest tests/test_image_detection_api.py`.

### Week 3: High-Throughput Batch Processing (Task 2)
- **The Problem:** In production, users or automated pipelines upload dozens of images at once. Calling inference on one image at a time in a loop is slow and wastes GPU resources.
- **Our Batch Solution (`predict_batch()` in [`src/image_detector/service.py`](src/image_detector/service.py)):**
  1. **Tensor Collation:** We stack individual image tensors together into a single 4D batch tensor `(B, 3, 224, 224)`.
  2. **Single GPU Forward Pass:** The model evaluates all images in the batch together with parallel matrix multiplication on the GPU. This gives an immediate **~2.3x throughput speedup** compared to sequential processing.
  3. **Dynamic Chunking ($B \le 32$):** If someone submits many images, we dynamically chunk them into groups of $\le 32$ so the GPU never runs out of memory (zero OOM risk).
  4. **Fault-Isolated Partial Failure:** If a user submits 5 images and image #3 is corrupted or empty, the entire request does **not** fail. Images #1, #2, #4, and #5 are processed successfully, and image #3 is safely captured in the `errors` list with an exact explanation.
- **Batch API Endpoints:**
  - `POST /api/detect/image/batch` (Upload multiple image files at once)
  - `POST /api/detect/image/batch/base64` (Submit a JSON array of Base64 images)
- **Verification:** Run `python3 scripts/verify_sprint2_week3.py` or `pytest tests/test_batch_processing.py`.

### Week 4: Grouped Input Sample Testing & Baseline Evaluation (Task 3)
- **The Problem:** Image detection models should not be evaluated as a monolithic black box. Forensic performance varies drastically depending on the generative architecture (e.g. Diffusion models vs GANs) and the domain distribution (in-domain vs unseen holdouts). We need structured grouped evaluation across partitions, generators, and batch sizes.
- **Our Grouped Evaluation Solution (`GroupedImageEvaluator` in [`src/image_detector/evaluator.py`](src/image_detector/evaluator.py)):**
  1. **Multi-Dimensional Group Partitioning:** Automatically stratifies samples by:
     - *Ground Truth Class:* Real (`0`) vs AI-Generated (`1`).
     - *Dataset Split:* In-domain test (`cifake`) vs out-of-domain holdout (`genimage`).
     - *Generator Architecture:* CIFAR-10 real, ImageNet real, Stable Diffusion v1.4, Stable Diffusion (GenImage), Midjourney, and BigGAN.
     - *Batch Size Scaling:* Throughput and latency profiling across group sizes $1, 4, 8, 16, 32$.
  2. **Comprehensive Forensic Metric Computation:** For every group, calculates Accuracy, Precision, Recall, Specificity, F1-Score, Mean Confidence, Confusion Matrix ($TP, FP, TN, FN$), Total Latency, and Throughput (FPS).
  3. **High-Throughput Vectorized Execution:** Leverages our Week 3 `predict_batch()` engine with hardware acceleration (`mps` on Apple Silicon), processing samples at **176 to 364 FPS**.
  4. **Documented Baseline Reference:** Establishes the formal pre-fine-tuning baseline benchmark on 400 real dataset samples, saved in [`docs/image_baseline_results.md`](docs/image_baseline_results.md) and [`results/image_baseline_evaluation.json`](results/image_baseline_evaluation.json), ready for Sprint 3 fine-tuning and ensemble tuning.
- **Verification:** Run `python3 scripts/verify_sprint2_week4.py`, `python3 scripts/evaluate_image_baseline.py`, or `pytest tests/test_grouped_image_evaluation.py`.

### Week 6: Advanced Forensic Evidence Inspection, Threshold Calibration, and Audit Certification (Task 4)
- **The Problem:** In legal, journalistic, and institutional forensic investigations, a binary label ("AI" vs "Real") with fixed default $\tau = 0.5$ is insufficient. Analysts must dynamically calibrate detection sensitivity, isolate individual color channels and frequency textures to pinpoint latent diffusion grid irregularities, inspect cryptographic evidence fingerprints, and generate printable chain-of-custody compliance certificates.
- **Our Forensic Interaction Suite:**
  1. **Interactive Decision Boundary & Threshold Controller ([`DecisionBoundaryController.tsx`](frontend/src/components/image-detection/DecisionBoundaryController.tsx)):**
     - Dynamic threshold slider $\tau \in [0.10, 0.90]$ with step $0.01$ and operational presets (`High Sensitivity 0.35`, `Balanced Baseline 0.50`, `High Specificity 0.75`).
     - Real-time margin calculation ($\Delta = |P(AI) - \tau|$) and calibrated confidence tiering:
       - *High-Confidence Synthetic Generation* ($P \ge 0.85$)
       - *Synthetic Diffusion Traces Detected* ($P \ge \tau \land \Delta \ge 0.05$)
       - *Borderline Ambiguous Evidence Zone* ($\Delta < 0.05$)
       - *Plausible Natural Photographic Capture* ($P < \tau \land \Delta \ge 0.05$)
       - *High-Confidence Natural Optical Sensor* ($P \le 0.15$)
  2. **Multi-Channel Forensic Evidence Visualizer ([`ForensicEvidenceViewer.tsx`](frontend/src/components/image-detection/ForensicEvidenceViewer.tsx)):**
     - In-browser HTML5 Canvas decomposition of evidence into 6 forensic view domains:
       - *Full RGB Color Domain* with zoom levels (100%, 150%, 200%).
       - *Luminance (Y)* channel ($Y = 0.299R + 0.587G + 0.114B$) exposing lighting inconsistencies.
       - *Spatial High-Pass Filter* revealing latent grid diffusion artifacts and compression blocks.
       - *Red, Green, Blue Chromatic Channels* isolating Bayer sensor pattern anomalies.
     - Real-time pixel coordinate HUD ($X, Y$) and RGB intensity probe under the cursor.
  3. **Printable Chain-of-Custody Audit Certificate ([`ForensicReportModal.tsx`](frontend/src/components/image-detection/ForensicReportModal.tsx)):**
     - Generates in-browser cryptographic **SHA-256 evidence fingerprint** using Web Crypto API (`crypto.subtle.digest`).
     - Formats formal investigation certificate with SKIT Department of CSE accreditation, investigator credentials (`Divisha Manak Bohra - 23ESKCA038`), hardware telemetry, and calibrated verdict.
     - One-click print/save as PDF (`window.print()`) and JSON audit log export.
  4. **Enhanced Batch Result Analytics ([`BatchResultsGallery.tsx`](frontend/src/components/image-detection/BatchResultsGallery.tsx)):**
     - Real-time filename search and dynamic batch threshold slider that re-classifies multi-image batches live.
     - Multi-criterion sorting (confidence high/low, latency, input order) and batch CSV/JSON manifest exports.

## Sprint 3 — Part 2: Dataset audit and unseen split
*User Story: Auditing the text dataset for label balance, sequence length, and data leakage, and constructing an honest out-of-domain unseen holdout split*

> [!NOTE]
> **Training Status:** Plainly stated, **NO training has been run**. The audit and holdout partitioning establish rigorous data hygiene, quantify baseline data leakage, and prepare an honest "unseen" test benchmark before any future fine-tuning occurs.

### 📌 Milestone Overview
- **Form-2 Sprint 3 Task 2:** *Auditing the RAID text manifest (`text_manifest.csv`) for class balance, token sequence lengths, cross-split duplicate leakage, and generator distribution; implementing the `--holdout-generator` and `--holdout-domain` partitioning pipeline in `scripts/prepare_text_dataset.py`; generating the separate unseen test manifest (`text_holdout_test.csv`); updating `finetune.py` with holdout evaluation hooks; and validating data partition invariants via automated unit tests.*

### 📁 Deliverables & Architecture

| Component | Path | Description |
|---|---|---|
| **Dataset Audit Script** | [`scripts/audit_text_dataset.py`](scripts/audit_text_dataset.py) | Standalone script computing counts per split/label, word length statistics (mean, median, 5th/95th percentiles), exact duplicates, normalized duplicates, and 3-gram Jaccard near-duplicates. |
| **Comprehensive Audit Report** | [`docs/text_dataset_audit.md`](docs/text_dataset_audit.md) | Structured markdown report detailing sequence length distributions, generator stratification flaws from Sprint 1, and cross-split leakage metrics. |
| **Holdout Partitioning Pipeline** | [`scripts/prepare_text_dataset.py`](scripts/prepare_text_dataset.py) | Enhanced data preparation script adding `--holdout-generator`, `--holdout-domain`, and `--input-manifest` to cleanly isolate unseen generative models into a dedicated test set while preserving default streaming behavior. |
| **Unseen Holdout Test Manifest** | [`datasets/splits/text_holdout_test.csv`](datasets/splits/text_holdout_test.csv) | Dedicated holdout test split containing 1,820 balanced samples (910 held-out `chatgpt` AI samples and 910 non-leaking human controls) with zero representation in `train` or `val`. |
| **Holdout Evaluation Hook** | [`services/text-service/training/finetune.py`](services/text-service/training/finetune.py) | Extended training script with `--holdout-manifest-path`, `--train-file`, and `--val-file` options to evaluate fine-tuned checkpoints on unseen holdout datasets and record `holdout_accuracy` and `holdout_macro_f1` in `metrics.json`. |
| **Audit & Holdout Test Suites** | [`tests/test_text_dataset_audit.py`](tests/test_text_dataset_audit.py), [`tests/test_text_holdout_split.py`](tests/test_text_holdout_split.py) | Automated unit tests verifying duplicate detection, length statistics calculation, holdout generator isolation, 50/50 balance, single-domain validation, and CLI argument parsing. |

### 📊 Dataset Audit Findings & Leakage Summary
- **Total Records:** 20,000 rows (`train`: 16,000, `val`: 2,000, `test`: 2,000) with exact 50% Human (`label=0`) and 50% AI (`label=1`) balance across all splits.
- **Word Length Statistics:** Overall Mean = 178.33 words, Median = 161.0, 5th percentile = 84.0, 95th percentile = 364.0 (Human: Mean = 175.05, Median = 171.0; AI: Mean = 181.62, Median = 137.0).
- **Exact Cross-Split Leakage:** 99 exact text duplicates between `train` and `val`; 79 between `train` and `test` (174 unique train texts leak into validation or test). 100% of exact leakage occurs in the Human class due to repeated source abstracts in the RAID corpus.
- **Near-Duplicate Leakage (3-gram Jaccard >= 0.85):** 618 validation samples (30.9%) and 607 test samples (30.4%) have >= 85% token overlap with training texts, highlighting why an isolated unseen holdout test set is essential for honest evaluation.
- **Generator Allocation Flaw Identified:** Sprint 1 AI records were split sequentially without shuffling, concentrating generators across splits (`train`: 9 generators, `val`: `mistral-chat` and `mpt`, `test`: `mpt` and `mpt-chat`). Holdout partitioning resolves this by stratifying remaining generators across train, val, and test.
