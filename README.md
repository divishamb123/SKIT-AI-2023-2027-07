## 📖 Plain-English Guide: What We Have Done in Sprint 1

In Sprint 1, we focused on two major goals: getting the image data ready and building the frontend authentication interface.

### Step 1: Image Dataset Collection (Task 1)
- We gathered a total of **132,000 images** to train and test our detector.
- The dataset combines two primary sources:
  1. **CIFAKE:** Real images from CIFAR-10 versus synthetic images generated by Stable Diffusion v1.4.
  2. **GenImage:** Real images and AI images created by multiple state-of-the-art generators (Stable Diffusion, Midjourney, BigGAN) used as our holdout benchmark.
- All paths, labels (`0` for real, `1` for AI-generated), and generator metadata are stored cleanly in [`datasets/splits/manifest.csv`](datasets/splits/manifest.csv).

### Step 2: Balanced Dataset Splits with Zero Leakage (Task 2)
- To ensure fair evaluation without bias, we divided the 132,000 images into four partitions:
  - **Train split:** 90,000 images (45,000 real, 45,000 AI) — exactly 50% / 50%
  - **Validation split:** 10,000 images (5,000 real, 5,000 AI) — exactly 50% / 50%
  - **In-domain Test split:** 20,000 images (10,000 real, 10,000 AI) — exactly 50% / 50%
  - **Out-of-domain Holdout split:** 12,000 images (6,000 real, 6,000 AI) — exactly 50% / 50%
- **Zero Data Leakage:** We strictly verified that no image appears in more than one partition. The split generation was done with a fixed random seed (`42`) so it can be repeated with 100% identical results.
- **Verification:** Run `python3 scripts/verify_sprint1_splits.py` or `pytest tests/test_dataset_splits.py`.

### Step 3: Reusable Authentication Components (Task 3)
- We created modular React/TypeScript UI primitives located in `frontend/src/components/`:
  - [`Input.tsx`](frontend/src/components/ui/Input.tsx): Clean text/password input with validation feedback.
  - [`Button.tsx`](frontend/src/components/ui/Button.tsx): Interactive buttons with loading spinners.
  - [`AuthCard.tsx`](frontend/src/components/auth/AuthCard.tsx): Styled card container for auth screens.
  - [`PasswordRequirements.tsx`](frontend/src/components/auth/PasswordRequirements.tsx): Real-time password strength checker that dynamically grades password security (Length, Uppercase, Numbers, Special characters).
  - [`FormAlert.tsx`](frontend/src/components/ui/FormAlert.tsx): Displays clear error and success messages to the user.

### Step 4: Responsive Login & Registration Pages (Task 4)
- Built complete, modern pages in Next.js:
  - [`/login`](frontend/src/app/(auth)/login/page.tsx): Secure sign-in form with live field validation.
  - [`/register`](frontend/src/app/(auth)/register/page.tsx): Sign-up form with password confirmation and strength indicators.
  - [`AuthContext.tsx`](frontend/src/context/AuthContext.tsx): Manages user login state and session tokens across the app.
- **Verification:** Run `node scripts/verify_auth_components.mjs` (25 automated checks pass 100%).

## 📖 Plain-English Guide: What We Have Done in Sprint 2

In Sprint 2, we built the actual image detection machine learning engine, wrapped it into an API, and added high-performance batch processing.

### Week 1: Core Image Detection Inference Engine (Task 1)
- **Model Choice:** We implemented a forensic classifier based on **ResNet-18** (`BaselineImageClassifier` in [`src/image_detector/model.py`](src/image_detector/model.py)).
- **Hardware Acceleration:** The code automatically detects your system's hardware. On an Apple Silicon Mac, it automatically runs on the Mac GPU using PyTorch `mps` (Metal Performance Shaders). On an NVIDIA machine, it runs on `cuda`. If no GPU is found, it safely falls back to CPU.
- **Image Preprocessing:** In [`src/image_detector/preprocessing.py`](src/image_detector/preprocessing.py), incoming images can be uploaded as raw file bytes, Base64 strings, or file paths. It converts images to standard 3-channel RGB, resizes them to 224x224 pixels, and normalizes them for the neural network.
- **Standardized Output Contract:** Every prediction returns a clean, typed response format:
  - `verdict`: `"REAL"` or `"AI_GENERATED"`
  - `confidence`: Confidence score from 0.0 to 1.0 (e.g., `0.9985`)
  - `probabilities`: Individual probabilities for `real` and `ai_generated`
  - `image_metadata`: Width, height, channels, and format
  - `latency_ms`: Processing time in milliseconds
  - `device`: Hardware device used (`mps`, `cuda`, or `cpu`)
- **Verification:** Run `python3 scripts/verify_sprint2_week1.py` or `pytest tests/test_image_inference_service.py`.

### Week 2: REST API & 6 Security Guardrails (Task 1)
- **FastAPI Endpoints:** Created in [`src/image_detector/api.py`](src/image_detector/api.py) and hosted as a standalone service in [`services/image-service/app/main.py`](services/image-service/app/main.py) on port `8004`:
  - `POST /api/detect/image`: Direct multipart file upload.
  - `POST /api/detect/image/base64`: Ingests Base64 image payloads.
  - `GET /internal/health`: Live health and hardware diagnosis endpoint.
  - `/docs`: Interactive Swagger UI in the browser.
- **6 Security Guardrails:** The API strictly validates every request and returns clear HTTP status codes:
  1. *Valid Upload:* Returns `200 OK` with the prediction.
  2. *Empty File:* Returns `400 Bad Request` if file has 0 bytes.
  3. *File Too Large:* Returns `413 Payload Too Large` if file exceeds 15 MB.
  4. *Unsupported Extension:* Returns `415 Unsupported Media Type` if not `.png`, `.jpg`, `.jpeg`, or `.webp`.
  5. *Spoofed Extension:* Returns `415 Unsupported Media Type` by checking actual magic byte file signatures (e.g., preventing an `.exe` file renamed to `.png`).
  6. *Corrupted File / Out-of-bounds Dimensions:* Returns `422 Unprocessable Entity` if the image cannot be decoded or is smaller than 16x16 or larger than 8192x8192.
- **Verification:** Run `python3 scripts/verify_sprint2_week2.py` or `pytest tests/test_image_detection_api.py`.

### Week 3: High-Throughput Batch Processing (Task 2)
- **The Problem:** In production, users or automated pipelines upload dozens of images at once. Calling inference on one image at a time in a loop is slow and wastes GPU resources.
- **Our Batch Solution (`predict_batch()` in [`src/image_detector/service.py`](src/image_detector/service.py)):**
  1. **Tensor Collation:** We stack individual image tensors together into a single 4D batch tensor `(B, 3, 224, 224)`.
  2. **Single GPU Forward Pass:** The model evaluates all images in the batch together with parallel matrix multiplication on the GPU. This gives an immediate **~2.3x throughput speedup** compared to sequential processing.
  3. **Dynamic Chunking ($B \le 32$):** If someone submits many images, we dynamically chunk them into groups of $\le 32$ so the GPU never runs out of memory (zero OOM risk).
  4. **Fault-Isolated Partial Failure:** If a user submits 5 images and image #3 is corrupted or empty, the entire request does **not** fail. Images #1, #2, #4, and #5 are processed successfully, and image #3 is safely captured in the `errors` list with an exact explanation.
- **Batch API Endpoints:**
  - `POST /api/detect/image/batch` (Upload multiple image files at once)
  - `POST /api/detect/image/batch/base64` (Submit a JSON array of Base64 images)
- **Verification:** Run `python3 scripts/verify_sprint2_week3.py` or `pytest tests/test_batch_processing.py`.
