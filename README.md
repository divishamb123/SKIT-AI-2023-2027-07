# 🖼️ Image Detection Modality & Interface (Divisha Manak Bohra — `23ESKCA038`)

## 1. Core Deep Learning Engine (`src/image_detector/`)

The image forensic detection engine is built inside [`src/image_detector/`](src/image_detector/) and provides real-time detection of synthetic images generated by diffusion models and GANs.

```mermaid
flowchart TD
    subgraph INGESTION ["1. Ingestion & Preprocessing"]
        Input["Image Input<br/>(Bytes / Base64 / File / PIL)"] --> Decoder["decode_image()<br/>Format Verification"]
        Decoder --> RGB["Channel Normalization<br/>(RGBA / Grayscale → 3-Ch RGB)"]
        RGB --> Preprocessor["preprocess_image_tensor()<br/>(224x224 Bicubic + ImageNet Norm)"]
    end

    subgraph ENGINE ["2. Neural Inference Engine"]
        Preprocessor --> Hardware["Hardware Dispatcher<br/>(MPS / CUDA / CPU)"]
        Hardware --> ResNet["BaselineImageClassifier<br/>(ResNet-18 Backbone)"]
        ResNet --> Softmax["Softmax Probability Layer"]
    end

    subgraph CONTRACT ["3. Strictly Typed Response"]
        Softmax --> Calibrator["Verdict & Confidence Calculator<br/>(REAL vs. AI_GENERATED)"]
        Calibrator --> Schema["ImageInferenceResponse<br/>(Pydantic Contract)"]
    end
```

## 2. High-Throughput Batch Processing Engine

To handle production-scale workloads, `ImageDetectionService` implements vectorized batch tensor collation and dynamic chunking:

```mermaid
flowchart TD
    subgraph BATCH_IN ["Batch Ingestion"]
        BatchIn["Multi-Image Input<br/>(Multipart Files / Base64 Array)"] --> SizeCheck{"Batch Limit Check<br/>1 ≤ B ≤ 32"}
        SizeCheck -->|B > 32| Err400["HTTP 400: BATCH_TOO_LARGE"]
        SizeCheck -->|Valid| Collate["Decode & Collate<br/>Stack into (3, 224, 224) Tensors"]
        Collate --> Fault["Partial Failure Isolator<br/>(Captures malformed items into errors)"]
        Collate --> Chunker["Dynamic Chunking<br/>Split into sub-batches (size ≤ 32)"]
    end

    subgraph VECTOR_ENGINE ["Vectorized GPU Inference"]
        Chunker --> TensorStack["torch.stack()<br/>4D Tensor (B_chunk, 3, 224, 224)"]
        TensorStack --> GPU["GPU / MPS / CPU Dispatch"]
        GPU --> ForwardPass["Single Batched Forward Pass<br/>logits = model(chunk_tensor)"]
        ForwardPass --> VectorSoftmax["Vectorized Softmax Layer<br/>Parallel Class Probability Matrix"]
    end

    subgraph CONTRACT_OUT ["Standardized Response Contract"]
        VectorSoftmax --> ResultsList["List[ImageInferenceResponse]"]
        Fault --> ErrorsList["List[BatchItemError]"]
        ResultsList --> Aggregator["BatchSummary Aggregator<br/>(Real/AI counts, mean confidence, latency)"]
        Aggregator --> FinalContract["BatchImageDetectionAPIResponse"]
    end
```

### Performance & Throughput Acceleration

| Metric | Sequential Processing (`predict`) | Batch Processing (`predict_batch`) | Vectorized Improvement |
|---|---|---|---|
| **8-Image Processing Time** | ~240 ms (30.0 ms/image) | ~106 ms (13.3 ms/image) | **~2.27x Throughput Acceleration** |
| **Memory / VRAM Safety** | Single item allocation | Dynamic chunking ($B \le 32$) | Zero OOM risk under heavy payloads |
| **Fault Resilience** | Pipeline aborts on error | Fault-isolated per-item errors | Valid items complete successfully |

## 3. Multi-Tier Security & Input Validation Guardrails

The public API enforces strict HTTP status codes and validation guardrails:

| Condition / Fault | HTTP Code | Error Code | Enforcement Mechanism |
|---|---|---|---|
| **Valid Image Upload** | `200 OK` | — | Returns verdict (`REAL`/`AI_GENERATED`), confidence, class probabilities, and latency. |
| **Empty File** | `400 Bad Request` | `EMPTY_PAYLOAD` | Rejects 0-byte uploaded files or blank base64 strings. |
| **Batch Ceiling Exceeded** | `400 Bad Request` | `BATCH_TOO_LARGE` | Rejects batch submissions with $> 32$ items. |
| **File Exceeds Max Size** | `413 Payload Too Large` | `PAYLOAD_TOO_LARGE` | Enforces a strict 15 MB upload limit. |
| **Unsupported Extension** | `415 Unsupported Media` | `UNSUPPORTED_EXTENSION` | Allows only `.png`, `.jpg`, `.jpeg`, `.webp`. |
| **Spoofed Magic Bytes** | `415 Unsupported Media` | `INVALID_MAGIC_BYTES` | Inspects binary file signatures (e.g. `\x89PNG`, `\xFF\xD8\xFF`, `RIFF...WEBP`). |
| **Corrupted Payload** | `422 Unprocessable` | `CORRUPTED_IMAGE` | Rejects truncated or unidentifiable image bitstreams. |
| **Dimension Bounds** | `422 Unprocessable` | `DIMENSION_TOO_SMALL` / `DIMENSION_TOO_LARGE` | Validates image dimensions ($16 \times 16 \le \text{dim} \le 8192 \times 8192$). |

# ✍️ Text Detection Modality & Frontend (Aryansh Agarwal — `23ESKCA021`)

## 1. Text Detection Microservice (`services/text-service/`)
- **Model Backbone:** `microsoft/deberta-v3-base` pretrained transformer for synthetic text classification.
- **Endpoints:** `POST /detect` and `GET /health` on port 8007.
- **Data Contract:** `TextDetectionRequest` (`text: str`) and `TextDetectionResponse` (`label: Literal["ai", "human"]`, `confidence: float`).

## 2. Text Benchmark Dataset
- **Corpus:** 20,000-sample balanced benchmark from `liamdugan/raid` across 11 generators (ChatGPT, Cohere, LLaMA, Mistral, GPT-4).
- **Splits:** 16,000 train, 2,000 validation, 2,000 test recorded in [`datasets/splits/text_manifest.csv`](datasets/splits/text_manifest.csv).

## 3. Frontend Architecture & Adapter Wiring
- **Stack:** Next.js 16 (App Router), TypeScript, Tailwind CSS.
- **Gateway Integration:** Connected `frontend/src/app/text-detection/page.tsx` to `POST /api/v1/detect/text` with Axios client adapters, dynamic gauges, and error alerts.
